## Z1: 코어 (TDD)

1. **countdown d-포맷** — `EventEngine.countdown(to:from:)`: 총 시간 ≥ 24h면 `"{d}d {h}h {m}m"`, 그 외 기존("Xh Ym"/"Ym"). 기존 테스트 보존 + 신규 테스트(25h→"1d 1h 0m", 정확 경계 24h).
2. **컴백 감지** — `UsageStore`에 `consumeComebackGap(minimumGap: TimeInterval = 3*3600, now: Date) -> TimeInterval?`: addEvents 시 직전 최신 이벤트 timestamp와 새 배치의 최소 timestamp 간 공백을 내부 기록(`pendingComebackGap`), consume 시 반환+클리어. 주의: 앱 시작 직후 8일치 로그 일괄 적재 시 오발화 금지 — **첫 addEvents(초기 로드)는 공백 기록 안 함** (플래그). 테스트: 공백 감지, 첫 로드 미발화, threshold 미만 nil, consume 후 nil.
3. **HUDEvent.Kind에 `case comeback`** 추가 (HUDView exhaustive switch 보정 — 아이콘 `figure.wave` / .cyan).

커밋: `feat: d-포맷 카운트다운 + 컴백 감지 (v0.7 코어)`

## Z2: UI/배선 + 적응형 조사

1. **J1/J2 첫 진입 애니메이션** — DashboardPanelController.toggle 열기 경로에서 `openCount += 1`을 rootView에 전달(컨트롤러가 hosting rootView 재설정 또는 @Observable 토큰 객체 주입) → DashboardView가 `.id(openCount)`로 콘텐츠 재생성 → onAppear 애니메이션이 패널 표시 후 재생. 시작에 0.1s 지연. 개요 GaugeBar 채움을 ProjectsTab StackBar와 동일한 grow(같은 duration/curve/stagger)로 통일. **검증 필수: 첫 클릭에 개요 게이지가 차오르고 숫자가 카운트업되는지 스크린샷/관찰.**
2. **J6 알약 카운트다운** — WavePill % 오른쪽에 9pt `.secondary` 텍스트: 현재 로테이션 서비스의 표시 윈도우 resetsAt(없으면 approxFullReset "~") countdown. settings.hudShowsCountdown(기본 true)일 때만.
3. **J9 설정 HUD 섹션** — `hudShowsPercent`(기본 true), `hudShowsCountdown`(기본 true) AppSettings 추가 + SettingsView "HUD 표시 정보" 섹션 + WavePill 반영 (% 끄면 점+웨이브+카운트다운만).
4. **J8 컴백 배선** — App.refresh()에서 `store.consumeComebackGap()` non-nil이면 HUDEvent(kind: .comeback, title: "다시 달려볼까요!", subtitle: "{countdown 포맷} 만에 AI 작업 재개", percent: nil) showHUD (기록에도 남음).
5. **J4/J5 적응형 개선 + 조사**
   - 조사: HUDView/DashboardView/패널에서 고정 색(white 계열 등) 사용처 grep — `.foregroundStyle(.primary/.secondary)` 시맨틱으로 전환 가능한 곳 전환 (서비스 색/상태 색은 유지 — 양 모드 가시성 OK).
   - 패널 `appearance` 강제 없는지 확인 (nil 유지). glassEffect 콘텐츠의 시맨틱 색은 시스템이 배경 밝기에 따라 vibrancy로 자동 반전 — 이것이 표준 적응 방식.
   - 확장 카드가 "자체적으로 어두워지는" 현상: 콘텐츠 면적/불투명 요소(예: 배경 박스, 진한 색 게이지 트랙) 때문에 glass가 어둡게 샘플링될 수 있음 — 불투명 배경 요소(.quaternary 박스 등)가 카드에 있으면 투명도 완화. 시도 후 비교 스크린샷. **확실한 개선만 적용, 애매하면 보고만** (사용자 방침).
   - 보고서에 "다른 앱들의 적응형 처리 방식" 요약 포함 (시맨틱 색+vibrancy, 머티리얼 변형, 수동 luminance 샘플링은 비표준).
